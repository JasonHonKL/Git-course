你敲下 git commit，屏幕上只多了一行哈希。可磁盘上真正发生的变化，在 .git 里：几个新文件，和一个被改写的指针。我们跟着这次提交，走一遍。

Git 其实只有三层：不可变的对象库，记录待提交快照的索引，和可移动的引用。对象按内容命名，引用只是一个文件。提交，就是把这三层接起来。

git add 先读文件，把内容写成 blob；再在索引里记下路径、哈希和 stat 信息。它不写 tree，也不写 commit。stat 缓存让 status 先比元数据，不必每次都读文件。

commit 时，先 refresh 索引，cache-tree 只为变化的目录写 tree；然后 commit 对象把树、父提交和作者信息绑在一起；最后引用事务移动分支。cache-tree 复用没变的目录，所以大仓库提交也不用重扫全部文件。

引用更新先写锁文件，用原子改名替换分支，再追加 reflog。对象没有变，变的只是一个写着哈希的文件。amend 和 rebase 也是这样：造新对象，移旧引用。

所以读 Git 源码，先找对象，再找引用，最后看它们在哪里被接起来。下一节，从 .git 目录开始。
